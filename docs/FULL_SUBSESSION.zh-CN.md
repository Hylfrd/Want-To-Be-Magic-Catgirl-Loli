# Full subsession 协作协议

本文件是 `FULL_SUBSESSION.md` 的中文译版。仅在用户明确开启本模式时适用，并遵守根目录 `AGENTS.md` 的目标范围、验证、AI 记录和 Git 规则。

正式产品名为 **Wayglint**；Catgirl 仅是现有仓库／开发代号。产品与 UI 任务必须在相关 DRD 和路线图合同之外读取 [BRAND.md](BRAND.md) 的名称、图标和主题。已有仓库名、路径与历史记录不作为视觉设计参考。


### 激活与角色

- 只有明确请求为一个根任务开启 `full subsession` 或 `full session` 时才激活。讨论或编辑规则不激活模式。只有 Main 拥有用户的根 `/goal`。
- 委派会话在现有项目目录中使用 local 环境，不请求工作树或分支初始化。激活表示在工具权限范围内请求创建独立的侧边栏委派聊天及协调消息。不得使用内置或隐藏 Subagents。本模式覆盖 Markdown 中的默认委派偏好，不覆盖更高优先级或工具规则；工具不可用时如实报告，不替换会话拓扑。
- Main 和 Submain 使用 `gpt-6.1-sol` / `xhigh`；实现、整合和审核 Subsession 使用 `gpt-6-luna` / `max`。保留 Main 的身份和设置。按已配置的 500k 上下文设计，不无必要地填满窗口。
- Main 规划中任务、额度、依赖和根任务验收，并管理 Submain。Submain 规划小任务并管理自己的 Subsession。指挥角色通常不实现产品代码。
- 同一问题经过两轮修复仍失败时，Submain 重新判断原因，并可亲自进行有边界的修复；记录该例外。Main 可执行确定的 Git 整合操作；代码修改和冲突修复交给委派任务。所有提交直接进入现有 `main`；只有 Main 协调串行 Git 写入和远程推送，子会话不自行推送。禁止创建分支、tag、issue、PR 或绕行工作树。

### 本地状态与上下文恢复

- 派发前，将状态持久化至已忽略的 `runtime/full-session/<goal-id>/`。不为本模式建设数据库、daemon、编排框架、CI 门禁或 telemetry 系统。
- `goal.md` 保存原目标、排除项、验收、模式、身份及状态路径；`plan.md` 保存中任务及依赖；`overview.md` 保存简短状态；`medium/<id>.md` 保存小任务计划；`results/<id>.md` 保存交接；必要时使用 `manual-tests.md`。
- Main 负责根状态、额度和登记表；Submain 负责中任务计划；执行会话负责结果和日志。每个文件只有一个写入者。每个聊天都得到现有工作目录中同一个明确的 `state_root`。状态丢失时从父会话恢复，不自行编造。
- 启动、每个新轮次、中断或压缩后，以及派发或整合前，读取相关状态：角色、任务及父/根 ID、模式、范围、额度、依赖和下一步。不得只依赖压缩后的历史。
- 在启动提示和恢复交接中重复核心要求：仅侧边栏聊天、角色与模型、范围限制、禁止子会话推送、并发上限 12。Main 读取总览及相关条目，其他角色读取自己的任务与约定。不反复加载完整计划、仓库地图、历史和对话全文。

### 规划与并发

- 实现派发前确定所有中任务的范围和验收；小任务也要先确定再派发。每项任务记录 ID 及对应需求、结果、负责人、修改范围、输入或约定、依赖、验收、粗略时长、状态、结果或提交、阻塞。
- 中任务以约一小时为目标，小任务以一至两个上下文窗口内完成为目标。估时仅为近似值；按可交付边界拆分，不以耗尽上下文或计时器到点后丢弃工作为边界。
- 使用依赖图，及时派发已就绪的独立工作，优先推进能解锁后续工作的任务。不为填满并发制造工作，不让有依赖的修改抢跑。固定目标和验收；记录范围内有依据的拆分、重排或纠正。可选改善需要用户授权。
- Main 控制所有预留额度：`1 + Submains + Subsessions <= 12`，最多 4 个 Submain、9 个执行会话。4 个 Submain 留下 7 个执行槽，2 个留下 9 个。明确分配额度，Submain 不得自行超额或相互转让。
- 启动前预留槽位，计入待启动、启动中、运行中、整合和审核会话。只有确认完成或停止并保存交接后才释放。派发或重试前核对实际聊天、文件负责人和 main 提交。每项任务只有一个实现负责人；创建请求、归档状态和本地状态文件不能证明启动、停止或完成。

### 交付与记录

- 执行会话在现有 `main` 工作目录中使用互不重叠的文件负责人；同一文件修改必须串行。Submain 向 Main 申请 Git 写入窗口，再交给执行会话串行完成暂存和提交。暂存只包含本任务文件；无关已暂存工作阻塞本次提交，不取消暂存或纳入它。禁止创建分支、tag、issue、PR、工作树或 detached 提交来隔离任务；每个实现及 AI 记录检查点都直接提交到 `main`。
- 详细产物直接保存为文件或提交，向后续任务传递原始引用。执行会话向 Submain 汇报。Submain 仅为中任务交付、跨任务依赖、额度变动、未解决阻塞或用户决定联系 Main；修复往返、源码和完整工具输出不进入 Main。
- 中任务交接包含 ID 及状态、已交付需求、起始与最终 main 提交、本任务所属的准确提交清单、证据路径、剩余检查或阻塞、所需行动。只有必要的决定才加载细节。
- 提交代表已提交审核，不代表已接受。依据约定审核准确提交，并验证组合后的中任务行为。代码变化后重查受影响部分；main 上其他任务的交错提交不算作本任务提交。检查期间相关文件正在变化时，等待对应写入者结束并保存检查过的版本，不另建测试分支。审核者区分阻塞与建议，遵守根目录 `AGENTS.md` 第 0 节，达到验收即停止。
- Main 依据证据检查每条原始需求，通过 Submain 委派最终整合与验收。验收打勾必须引用证据，仅有执行者声明不充分。
- 所有 Submain、执行会话记录在 `ai-logs/subagent/`，保留直接父会话及根会话身份。依照根目录 `AGENTS.md` 第 1—4 节保存原始对话并单独提交。从会话源导出及去重，不将对话全文打印进 Main；只返回路径、覆盖范围和缺口。运行摘要不得替代对话。

### 归档

- 确认会话已无剩余任务或决策，且工作、交接和日志已保存时，及时归档完成和失效的聊天。保留下一阶段仍需要的会话，以及仍需使用的交付物和任务文件。

### 阻塞与完成

- 反复失败时，保留提交、未完成修改、失败方法、阻塞和下一步。继续独立工作并逐级上报。不重复查询未变化状态，不静默遗漏必需任务。
- 待实机检查记录构建或提交、前提条件、操作、预期结果和缺失证据。完成独立工作，将人工清单汇总给 Main。
- 只有原始验收已有证据、任务所属工作和记录已提交、没有剩余必需任务或决定，才完成根 Goal。验收要求人工结果时等待用户；约定以可测试版本交付为终点的 Goal，可以完成，但明确标注设备验收待执行。
- 归档聊天或退役临时状态前，核对所有子任务并保留证据。任务完成不授权维护、监控或额外改善。
